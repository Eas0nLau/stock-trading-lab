# 指数周期与热门板块情绪数据任务设计

## 背景

前端的 `IndexCycle` 和 `HotBoardEmotion` 页面已经有读取接口、字段转换和图表展示，但当前数据库中的原始行情表、韭研公社异动表和两类分析表均为空。接口只能返回“请先执行每日更新”。公开仓库缺少原有 `task` 包，因此需要依据现有表结构和算法补全从采集到落库的任务链。

本次只覆盖以下闭环：

1. 上证指数日线和股票日线基础数据。
2. 韭研公社异动榜单及板块股票池。
3. 指数情绪周期和市场宽度分析。
4. 热门板块隔日承接情绪分析。
5. 每日任务、历史回补、幂等写入和测试。

不重建龙虎榜、DDE、5 分钟 K 线、盘前纪要等其他任务。

## 目标与非目标

### 目标

- 现有两个页面在完成首次数据回补后返回 `状态=success`。
- 保持现有 API 响应字段、数据库表结构和情绪评分算法口径。
- 任务可按指定交易日重跑，重复执行不产生重复数据或错误覆盖。
- 每日任务在收盘后按依赖顺序运行，并使用 Redis 防止并发。
- 对网站、行情源或单日数据不完整提供明确日志，不写入伪造的分析结果。

### 非目标

- 不把东方财富板块数据替换为韭研公社数据。
- 不改变前端图表或 API 契约，除修复指数落库结果读取遗漏字段外不改读取逻辑。
- 不要求通达信客户端参与每日数据任务。

## 数据流

```text
Tushare stock_basic  ────────> stock_basic
Tushare daily       ────────> stock_daily ────────┐
                                                   ├─> 市场宽度
AkShare 上证指数日线 ───────> akshare_sh000001 ───┤       └─> t_指数情绪周期_市场宽度
                                                   └─> 指数评分 ──> t_指数情绪周期_每日分析

韭研公社异动接口 ───────────> t_韭研公社异动解析 ──┐
                                                   └─> 热门板块隔日分析 ──> t_热门板块情绪_每日分析
```

交易日期以 `akshare_sh000001` 的日期序列为准。热门板块分析的 `样本来源日期` 必须是当前交易日的上一交易日，不能使用自然日减一天。

## 组件设计

### `task/每日更新.py`

提供现有应用调用需要的 `tasks(date)` 函数，并提供历史回补入口。编排顺序：

1. 获取目标交易日及其前一交易日。
2. 更新 `stock_basic`。
3. 更新目标日期及指数计算窗口所需日期范围的 `stock_daily`。
4. 更新 `akshare_sh000001`。
5. 调用韭研公社异动采集。
6. 计算并 upsert 热门板块情绪。
7. 计算并 upsert 市场宽度和指数周期。
8. 所有目标分析写入成功后设置 Redis 完成标记。

每日任务使用 `run_check:每日更新.py` 作为运行锁，使用 `每日更新.py:{date}` 作为完成标记。锁必须设置过期时间，并在异常时释放；数据库主键 upsert 是最终幂等保障。

历史回补入口默认覆盖最近 60 个交易日，使指数 MA60、指数波动图和热门板块近 30 日趋势具备数据。回补以实际可采集日期为边界，不把不可获得的历史韭研数据标记为成功。

### `task/_5_韭研公社异动.py`

保留 README 中的公开调用名 `韭研公社异动采集(date)`。复用 `utils.driver_chrome` 的项目 Chrome profile 和 `listen.steps()` 模式：

- 打开指定日期的韭研公社异动页面。
- 监听 `/jystock-app/api/v1/action/field`。
- 解析板块名称、板块个股数量、股票代码、股票名称、涨停时间、几天几板、涨幅和涨停解析。
- 仅保留涨幅 9.5% 至 10.2% 的涨停附近记录，与 README 的原有口径一致。
- 使用稳定的 `data_id` 生成规则写入 `t_韭研公社异动解析`，同一日期、板块和股票重跑时更新而不是新增重复行。
- 对响应为空、页面超时、字段缺失和网站返回错误分别记录原因；采集不完整时返回失败状态，阻止当天热门板块分析落库。

输出 INI 文件不是本次页面闭环的必要依赖，可以作为独立的后处理步骤，不影响数据库分析任务。

### 指数分析落库

复用 `实时监控/情绪周期.py` 已有的计算函数：

- `读取上证指数日线()`
- `读取市场宽度数据()`
- `计算指数周期结果()`

新增任务层负责将结果拆分写入：

- `t_指数情绪周期_市场宽度`：日期、股票数量、涨跌数量、涨跌超 5%、涨跌停、全市场成交额和平均涨跌幅。
- `t_指数情绪周期_每日分析`：指数行情、均线、斜率、五项分数、JSON 图表字段和完整结果 JSON。

两张表均使用日期主键 `ON DUPLICATE KEY UPDATE`。分析结果写入前必须确认指数日线和市场宽度都有目标日期数据。读取端的 `SELECT` 同时补上 `完整结果JSON`，让已有的完整结果快速恢复分支真正可用。

### 热门板块分析落库

任务按当前日期和上一交易日从 `t_韭研公社异动解析` 读取板块股票池：

- 同一板块的股票按股票代码去重。
- 当前日行情从 `stock_daily` 批量读取，并限制为沪深主板、非 ST 股票。
- 调用 `utils/热门板块情绪算法.py::生成每日分析()`，不复制或修改现有评分规则。
- 将返回字段映射到 `t_热门板块情绪_每日分析`，`判定依据` 序列化为 `判定依据JSON`。
- 按 `(日期, 板块)` 批量 upsert。

前日榜单或当日榜单缺失时不生成“看起来完整”的结果。只有明确完整的两日榜单和可接受行情覆盖率才写入正常分析；数据不足状态由现有算法表达，数据源缺失则任务失败并保留日志。

## 错误处理与恢复

- 网络采集使用有限重试和递增等待，不使用无限递归重试。
- Chrome 页面关闭或连接断开时，重新初始化项目 profile 后重试当前采集日期。
- Tushare 或 AkShare 单日失败时记录日期、接口和异常，任务不推进到依赖该数据的分析阶段。
- 数据库批量 upsert 使用事务；失败时回滚当前批次，不设置每日完成标记。
- 历史回补允许从失败日期重新开始，已成功日期通过主键 upsert 安全重跑。
- API 继续返回当前已有的 empty 信息，但任务日志要给出实际缺失表、日期和数据源原因。

## 测试设计

### 单元测试

- 韭研接口响应解析：完整响应、空响应、字段缺失、重复股票和涨幅过滤。
- 日期工具：交易日上一日、周末跳过、目标日期格式化。
- 指数结果到两张表的字段映射和 JSON 序列化。
- 热门板块算法接收前后两日股票池与行情后的结果字段。

### 数据库集成测试

- 三张分析表首次 upsert 写入一条记录。
- 同一日期重复 upsert 不增加行数且更新指标。
- 分析依赖缺失时不写目标分析表。
- `完整结果JSON` 能被 API 读取端恢复。

### 任务集成测试

- 用固定夹具模拟 Tushare、AkShare、韭研响应，执行一个交易日任务并检查三张分析表。
- 执行两次同一日期任务，验证行数和主键稳定。
- 模拟一个数据源异常，验证 Redis 完成标记未设置、锁被释放。
- 首次回补使用有限日期夹具，验证按交易日顺序执行。

## 成功标准

1. 空数据库执行历史回补后，`akshare_sh000001`、`stock_daily`、`t_韭研公社异动解析` 有实际日期数据。
2. `t_指数情绪周期_市场宽度` 和 `t_指数情绪周期_每日分析` 至少有一个完整交易日结果，指数周期页面返回成功。
3. `t_热门板块情绪_每日分析` 在韭研数据可用的日期有记录，热门板块页面返回成功。
4. 同一日期重复执行不产生重复主键。
5. 现有测试以及新增任务测试全部通过。
