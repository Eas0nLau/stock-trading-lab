# 韭研公社数据核对与热门板块情绪重算设计

## 目标

核对旧表 `t_韭研公社异动解析` 与新表 `jiuyan_actions`，将旧表中存在而新表缺失的记录补迁到新表，并基于补齐后的韭研数据重算热门板块情绪。

## 范围

- 只处理韭研公社异动数据和依赖它的热门板块情绪数据。
- 以 `data_id` 作为韭研记录的业务键。
- 不删除旧表数据。
- 不覆盖新表已有记录；只插入新表缺失记录。
- 不执行 `003_drop_legacy_schema.sql`。

## 数据流程

1. 查询旧表与新表的行数、日期范围和重复 `data_id`。
2. 查询旧表中不存在于 `jiuyan_actions` 的 `data_id`，按现有迁移映射转换字段并插入新表。
3. 重新核对两表的 `data_id` 差异，确认缺失集合为空。
4. 找出同时具备当前交易日和前一交易日韭研板块数据的日期。
5. 使用 `stock_lab.modules.emotion.jobs.run_hot_board_emotion_job`，以新表 `jiuyan_actions` 为唯一数据源，重算每个完整日期的热门板块情绪。
6. 按 `(trade_date, board_name)` upsert 到 `hot_board_emotion_daily`。
7. 输出迁移数量、覆盖日期、重算日期、板块数量和跳过原因。

## 一致性与异常处理

- 发现旧表重复 `data_id` 时停止，不自动猜测应保留哪条记录。
- 新表已有相同 `data_id` 时保持新表记录不变。
- 字段映射沿用 `002_migrate_legacy_data.sql`，包括股票代码补齐和涨幅等字段映射。
- 缺少前一交易日或当前交易日韭研数据的日期不重算，并记录为跳过。
- 每个日期的情绪重算使用事务写入；失败时该日期的结果不应产生部分写入。

## 实现形态

新增一个可重复执行的专用回补入口，复用现有数据库 client、market-data repository 和 emotion job。默认只核对不写入，真实补迁和情绪重算必须通过显式参数开启。

## 验证

- 单元测试覆盖业务键差异、字段映射、幂等重复执行和完整日期筛选。
- 数据库迁移测试确认新表字段和情绪表唯一键符合现有 schema。
- 实际执行后确认旧表缺失集合为空，`jiuyan_actions` 无重复业务键，情绪表 JSON 合法且日期覆盖符合完整韭研数据范围。
